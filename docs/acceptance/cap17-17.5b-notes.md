## Principles (written)

1. **Smoothness first.** If the 3s Timer / setState path is unclean under
   fast leave/re-enter, **drop Package B**; keep G1 + notes.
2. **Page center chrome must not cover Layer 1 / poster.** Center wait and
   fail slots only when coverless (no displayable cover). Exception:
   feed-level `mainBrowseFeedLoading` (“Loading library…”) remains centered
   — Session/resolve shell, not page L2 chrome. (Covered L2 **fail** may
   still paint reason + Retry over poster — pre-existing; not changed here.)
3. **Corner reassure is pure incremental.** It may show **with L1 / poster
   present** (corner only). It may also coexist with center
   `Layer2Waiting` when coverless. Dual copy is intentional when both
   doors fire (`W-17.5b-dual`); covered L1 must not get center wait
   (`W-17.5b-covered`).

## Scope expansion — fail Retry cancel-before-retry (Dart-only)

Device testing during 17.5b surfaced a pre-existing bug (not introduced by
Package B/C): fail-state Retry does not cancel the stale in-flight prepare
before starting a new one, so retry after network restoration can hang
indefinitely when Host still has `preparingAssetIds` for that id.

**Fix (Dart-side):** cancel-before-retry on fail Retry / resume-fail —
`PlaybackRepository.cancelInFlightPrepare` then load. Cap16 single
networked path unchanged. Locked by `W-17.5b-cancel-order*`.
