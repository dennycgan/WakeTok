### Known constraint (not a spike blocker)

> **Limited + KV lost → create-only duplicate "WakeTok" album risk:** Under
> Limited, list find is forbidden (ADR-021). If probe/product KV is cleared
> (reinstall / clear cache) but a `"WakeTok"` User Album already exists in
> Photos, `createAlbum` may create a **second** same-title album. Accepted
> cost of the no-list-find rule — for D1/D3 follow-up, not blocking 19.2a.

**Device observation (2026-09-01, A1):** Even **without** KV loss, each
L-BOOT probe run (Clear KV → create) adds **another** WakeTok User Album.
iOS Photos does not enforce unique album titles. **D1 bootstrap must treat
KV + `localIdentifier` as canonical identity**, not album title string.
**Confirmed on device** (repeated L-BOOT).
