## Orthogonal: feed Case B intermediate (not Cap 23)

Feed revisit after external delete can reach Host-unavailable **Case B**
(`mainBrowseFeedUnavailable` / feed dim — Cap 21.6 axis) via **more than
one** pre-B chrome. Observed on device (doom scroll / remount):

| Intermediate | Typical condition (not exhaustive) |
|--------------|--------------------------------------|
| Layer-1 loading copy (`_loading` miss) | Still shell not mounted yet / cold remount |
| One-frame black (still shell, no pixels) | Still cover tree already mounted; decode pending or broken |

**Not RNG:** same internal state → same chrome. **Path-dependent and
real:** remount, seed, bad path, and Host vs Image timing vary across
visits, so which intermediate appears is **unpredictable across rounds**
and **actually happens** on device — not a theoretical race only.

**Case B must not keep residual cover:** when Host / coerce lands
`assetUnavailable`, unload painted L1/L2 and use page-failed B chrome
(also evict Session L2-ready for that id). Do **not** stack Case B copy
over a sharp JPEG (owner device: swipe-away-3 → revisit). Recoverable
fails (download / network / in-library generic) still keep-cover.
**U-21.6-3b** locks the drop-cover rule.

**Case B → restore → ±1 revisit:** after Host Case B, leave + neighbour
preheat can leave preview L1 on the keep-alive page; become-current must
**not** `reuseLayer1` / `_retryLayer2Only` alone (owner: stuck on L1,
especially adjacent). Flag `_needsFullReloadAfterHostUnavailable` forces
full L1→L2 on next become-current. **Parked on B while Photos restores
(case 1) stays accepted — no auto-retry without leave.** **U-21.6-3e**.

**456a still Open:** Session L2-ready can still paint a deleted JPEG
**without** hitting Host this visit (no Case B yet). That limb is out of
Cap 23; distinct from the fixed Host-B + keep-cover stack.

**Case B sticky after Photos restore (same session) — accepted:** After
external delete/hide → Case B, then restore in Photos, that **feed slot
may keep Case B chrome for the rest of the Consumption Session**
(especially after long / far scrolling). **Not** “position cache lost”:
Session Queue **keeps** the id (ADR-044 D3; no mid-session rebuild / no
`PHPhotoLibraryChangeObserver`). Live Photos truth is not synced until
the page hits Host again (and Host may still fail briefly). Owner:
acceptable (rare). Leaving the pool and re-entering usually starts a
new Session and clears sticky Case B chrome — **high probability, not
guaranteed**. Distinct from ±1 L1-stuck (**U-21.6-3e**, fixed).

**FAIL discipline:** Cap 23.4 (B–E / G) judges Cap 23 mutation dialog +
Host write block. Do **not** FAIL (or “flake”) Cap 23 because feed
pre-B intermediate varied. Classic **456a** (L2-ready, no Host) ≠ FAIL
alone. Sticky Case B after restore (same session) ≠ FAIL alone. Cap 23
does **not** own feed Case B chrome.
