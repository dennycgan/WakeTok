## Residual triage — scrub preview bubble (debt **442** scope clarified)

**Owner observation (18.6 soak, acceptable but imperfect):**

1. **First scrub engagement:** preview bubble may appear after a short
   delay (no prior successful JPEG to borrow).
2. **Mid-drag in-flight / bucket switch:** solid `#000000` placeholder
   (or brief borrow when eligible) then replaces with the correct JPEG
   once Host completes — not permanent black (`7b4a0ff` drift-reject
   class eliminated).

These are the **same debt 442 architecture** as fast-drag strip
gaps — not a separate defect class. Trigger (2) and (3) are **not**
fast-drag-specific; every bucket switch clears the current frame and
waits on async Host return (BENCH typical **14–150 ms**; max **388 ms**
on sparse-GOP zero-tolerance decode).

**Verdict:** **Accepted (phase)** — not a Cap 18.6 fix target. Current
architecture (Host single-flight + async `AVAssetImageGenerator`, §2.1
borrow cap, Option B) **cannot** guarantee zero-latency zero-placeholder
preview at Photos parity. Optional future tuning: scrub-touch prefetch,
`maximumSize`; widening borrow remains out of scope (§2.1).

STATE **442 Item** rewritten in this docs commit to cover all three
trigger classes (not only fast horizontal drag).

## Residual triage — external Photos delete (new debt **444**)

**Verified (owner device, Kafka Profile `1ca0395`):**

- All tab: land on a still, **without quitting WakeTok**, delete that
  asset in iOS Photos, return to WakeTok, swipe back to the same feed
  item → **first** revisit still shows the image.
- Swipe away and return again → **Layer 2 fail** UI:
  `Could not load. Allow wireless data, then retry.` + Retry; Overlay
  metadata rows (relative date, `~ Y-M-D`, file size) still visible.

**Verified (code / existing mapping):**

- Fail copy is `mainBrowseFeedNetworkFailed` ← `FeedFailureReason.network`
  ← Pigeon `assetUnavailable` (`feed_page_media.dart`).
- Host `requestDisplayAsset`: `PHAsset.fetchAssets` empty →
  `assetUnavailable` / `"Asset not found"` (`PhotoLibraryService.swift`).
- Production codebase has **no** `PHPhotoLibraryChangeObserver` /
  session invalidation on external library mutation (deferred in ADR).

**Inferred (architecture — not log-verified in this session):**

- First revisit may still paint from **cached L2** (`DisplayTempFileStore`
  and/or in-page display state) while the Consumption Session queue
  still holds the deleted `localIdentifier`.
- Second remount likely takes a **fresh Layer 2 load** that hits the
  missing-asset Host path above.

**Verdict:** Misleading copy + stale session member — **Open** debt
**444**; owner plans fix under Capability Roadmap item **Build a Pool,
Ephemeral Pool, and Source ordering**. Not Cap 18.6 scope.
