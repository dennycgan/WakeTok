> **Status:** Complete (device smoke PASS, 2026-09-02).

## Positioning

**19.5b is a new phase**, not a reopen of 19.5. Cap 19.5 §7 item 1
(`album` + `canAddContent:true` only) remains closed. Favorites is a
**synthetic panel row** with a different PhotoKit mutation
(`PHAssetChangeRequest.isFavorite`) — not membership in a Smart Album via
`addAssetToAlbum`.

**Recommended schedule:** insert **19.5b** between **19.5** and **19.6**
(same half-sheet entry; independent of left-swipe). Final numbering is
owner’s call after this draft.

**Complexity class:** ~**19.2-level** (new Pigeon + Host write path +
read-on-open). Not a one-line picker patch.

## Agent stance on the five pre-gate questions

### 1 — Row semantics vs album rows (UI separation)

**Agree with owner.** Favorites must **not** look like album row #0.

| Element | Favorites row | Album rows (19.5) |
|---------|---------------|-------------------|
| Data source | Synthetic UI item | `listAssetSources` filtered |
| Leading | `star` / `star_fill` icon (no thumbnail) | Album cover thumbnail |
| Mutation | `setAssetFavorite` | `addAssetToAlbum` |
| Section | **“Quick action”** block above a divider | **“Albums”** list below |

Visual spec (device-polish tunable):

- Section label: `cap19PanelFavoritesSectionTitle` — muted `onMediaMuted`,
  `bodySmall`, 8dp top / 4dp bottom padding.
- Favorites row: full-width `InkWell`, min height 52dp, leading 28dp star,
  title `onMedia`, **no** trailing chevron.
- **Divider** (`onMedia` @ 12% alpha) between Quick action and Albums.
- Album list title: `cap19PanelAlbumsSectionTitle` (**Full Access only**).

**Full Access layout only** — Limited does not render Favorites, divider,
or album section (see §3).

### 2 — Toggle vs add-only

**Recommend B: Toggle** (owner-aligned).

| | Add-only (A) | Toggle (B) ✓ |
|---|-------------|--------------|
| Behaviour | Always `isFavorite = true` | Read state on open; tap flips |
| UX | Silent no-op if already favorited | Label/icon reflect state |
| vs kickoff “no undo in app” | Consistent with album append | **Documented exception** |

**Why Favorites may toggle but album append may not:**

- Album **removal** is a different Photos workflow (membership edit); kickoff
  §14 treats append as one-way in-app.
- **Favorite** is a first-class **binary asset flag** in iOS Photos; users
  expect the same toggle semantics as the system share sheet / detail view.
- Toggle does not require enumerating albums or exposing “remove from album X”
  in-app — it only flips a per-asset property on the **current** asset.

Copy (toggle):

| State | Title | Success toast |
|-------|-------|----------------|
| `isFavorite == false` | Add to Favorites | Added to Favorites |
| `isFavorite == true` | Favorited — Remove | Removed from Favorites |

Icons: iOS `CupertinoIcons.heart` / `heart_fill`; Android slot uses
Material star equivalents (`cap19_favorites_platform_icon.dart`).

**Sheet stays open** after Favorites toggle (unlike album append success
which dismisses). Rationale: toggle is reversible in-place; album success
is a completed “destination” action. Error → error toast, sheet stays.

### 3 — Limited Access

**Owner decision (2026-09-02): package-lock with albums — no Limited
special channel for Favorites.**

Even though a per-asset `isFavorite` write does not call
`listAssetSources`, the half-sheet must not mix interactive and
non-interactive rows under Limited. Users do not separate “favorite” vs
“add to album” at the PhotoKit API level; partial unlock would feel
inconsistent.

**Behaviour:**

| Access | Panel contents |
|--------|----------------|
| **Full** | Title → Favorites row → divider → Albums list (19.5) |
| **Limited** | Title → **existing 19.4 D4 block only** (generalized copy + Open Settings). **No** Favorites row. **No** album list. **No** new Limited branch code beyond the generalized D4 string. |

Limited path is a **regression guard** identical to **P-19.4-D4** — not a
new Limited UI design.

**Intentional asymmetry (not a doc error):** Cap 19 left-swipe append to
the fixed WakeTok album remains enabled under Limited (**ADR-040 D3=B**).
Panel Favorites + album picker stay Full-only (**D4**). Swipe and panel are
independent product entries; this draft does not reopen D3.

### 4 — Host / Pigeon (new surface)

**Do not reuse `addAssetToAlbum`.**

#### Pigeon additions (`waketok_platform_apis.dart`)

```dart
class AssetFavoriteStatusDto {
  AssetFavoriteStatusDto({
    required this.assetIdentifier,
    required this.isFavorite,
  });
  String assetIdentifier;
  bool isFavorite;
}

// PhotoLibraryApi:
AssetFavoriteStatusDto requestAssetFavoriteStatus(String assetIdentifier);
void setAssetFavorite(String assetIdentifier, bool favorite);
```

**Read path:** dedicated one-shot on sheet open (not bundled into
`PresentationMetadataDto` — avoids widening every metadata consumer in Cap
8/19 overlay paths). **Full Access only** — not invoked under Limited.

**Write path:** Host `PHAssetChangeRequest(for: asset).isFavorite = favorite`
inside `performChanges`.

**Error mapping (no new ErrorCode expected):**

| Condition | Existing code |
|-----------|---------------|
| Asset gone / not fetchable | `assetUnavailable` |
| No write access | `unauthorized` |
| User/system cancel | `operationCancelled` |

Verify on Host spike before coding; add ErrorCode only if PhotoKit surfaces
something unmapped.

### 5 — “Always first” without sort debt

**Structural synthetic row** — never inserted into `writableUserAlbums` /
`listAssetSources` sort.

```text
Cap19ActionsHalfSheet
├── Full Access:
│   ├── Cap19FavoritesRow          ← fixed slot 0
│   ├── section divider
│   └── Cap19AlbumPickerList
└── Limited Access:
    └── D4 message + Settings      ← unchanged structure (19.4)
```

Position is **layout**, not tie-break — immune to debt **445** ordering.
