## Mount allow / deny (Cap 29)

### Allowed

- Settings `ListView` section **Photos Access** (top), under existing Settings `SafeArea`.
- System Limited Library Picker (Host) and system Settings (`app-settings:`) — not App overlays.
- Reuse ARB strings listed in §5; new section title (+ Full status) keys only.
- Manage → `presentLimitedLibraryPicker()` only.
- Reuse `LimitedAccessBanner` **content/calls** inside Settings ListView for Limited; Full needs a separate status row (widget is Limited-shaped today).

### Forbidden

- Re-mount Limited banner (or any manage chrome) as shell `Column` sibling **above** `IndexedStack`.
- Browse top-chrome third tier / Open Settings row (layout notes §11.3 deferred; Create Limited helper stays the Browse-side Limited mute language).
- Browse launch / each-open remind banner (v1 explicit reject).
- UI-layer second `notifyAccessScopePossiblyChanged` or bare `restartSession`.
- Wiring Open Settings (Limited **or** Full) to authority notify.
- Product Settings entry that depends on `LibraryTotalsShellPage` / Debug smoke route.
- Inventing a third Limited “disabled” visual language (do not mix Action Column `Opacity 0.22` with top-chrome `onMediaMuted@0.35` into Settings — use normal Settings onSurface list styling).
