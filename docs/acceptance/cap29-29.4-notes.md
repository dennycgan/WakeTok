## Known cost — every-dismiss rebuild is now user-visible (D10)

**Not a Cap 29 fail; not a D10 rollback.** Same class as debts **480** /
**481**: accepted product cost recorded for honesty.

- **Contract (ADR-058 D4):** Limited picker **every dismiss** marks dirty
  (no selection-diff). Rebuild threshold is dismiss itself, **not** an
  actual change inside the picker. Cap 28.5 locked this; Cap 29 did not
  invent it.
- **Before D10:** that cost was mostly invisible — Snapshot cache often
  hit, queue/index often looked unchanged, so “rebuild” felt like a no-op.
- **After D10:** the cost is fully visible — open Manage, change nothing,
  dismiss, return to Browse → fresh resolve + jump to feed index 0.
  D10 correctly fixes “real selection change felt like nothing”; it also
  amplifies the every-dismiss tax under a different assumption than when
  D4 was first accepted. Owner re-confirmed accepting this new magnitude
  for Cap 29 close (2026-09-23).

**Future direction (out of Cap 29 — do not implement here):** after
resolve, compare the new ordered asset-id list to the pre-consume list;
if **identical**, skip the **visual** disruption (`setIndex(0)` / treat
as non-reshuffle for the user). Dirty mark, cache clear, and resolve
still run (ADR-058 D4 unchanged — still no PhotoKit selection-diff).
Precedent: Confirm `same-value` Confirm is a no-op aside from dismiss
(ADR-055 / Cap 27). Would need its own ADR if scheduled.
