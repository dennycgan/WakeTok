# Cap 18.5 acceptance notes — scrubber + progress-drag

Device: i17 Green Profile (local library videos); Kafka Profile prior passes for UI polish.

## Scrub second-granularity (Cap 18.5 scope)

**Decision:** Main Browse progress scrub is **whole-second** granular. iPhone may store
slow-mo / high-FPS assets with 0.01s edit resolution; Cap 18.5 does not expose sub-second
scrub in the feed UI or Host seek contract.

**Drag geometry:** The scrubber band is linear in time. Finger position maps to
`ratio ∈ [0, 1]` via inner track width (12px horizontal padding each side). While dragging,
thumb/fill follow the **continuous** ratio; only the numeric label and release seek are
quantized.

**Quantizer (label + seek on release):** `scrubberSeekSeconds` in `scrubber_policy.dart`:

```
wholeSecond = round(ratio × durationSeconds).clamp(0, durationSeconds.floor())
```

Examples on an 18s clip:

| Continuous drag time | Label + seek target |
|---------------------|---------------------|
| 00:03.41            | 00:03               |
| 00:03.71            | 00:04               |

Idle playback label (not dragging) still floors runtime `positionSeconds` for display —
Host observe ticks are not re-quantized on every frame.

**Why round (not floor):** Floor made the post-release playhead snap backward vs the drag
position (visible “瞬移”). Round minimizes landing error at second boundaries and matches
user expectation for “nearest second.”

**Cap 19.2c preview align (`0ef9ef2`):** Mid-path scrub preview request keys now use the
same round quantizer as label + release seek (`scrubPreviewRequestSeconds` →
`scrubberSeekSeconds`). End-cap / integer-duration EOS-safe still use `duration − ε`.
Cap 18.5 historically used floor for mid-path preview; that dual-quantizer seam was
illuminated by Cap 19.2b keep-playing and closed in 19.2c — **not** a 19.2b regression.
The round example table above still describes label + seek (and now mid-path preview).

**Future upgrade path:** To support 0.1s or frame-accurate scrub later:

1. Change quantizer + `formatScrubTimestamp` display (single source of truth).
2. Revisit Host `seek` tolerance / timeout (zero-tolerance + wall-clock cap today).
3. Preview bucket step (`kScrubPreviewBucketStepSeconds = 1.0`) and ADR-040 §2.1 borrow.
4. Keep linear ratio mapping; sub-second is a quantizer + preview pipeline change only.

## Timestamp label pairing

The resident label is omitted until Host reports `durationSeconds > 0`, then
paints `MM:SS / MM:SS` in one update. **Track + label share**
`scrubberResidentChromeVisible` — both stay hidden while Layer 2 is frozen or
duration is unknown, then appear in the same frame when L2-ready and duration
are both satisfied (reserved band height prevents layout jump).

## Scrub release reliability (work commits after `3d115a4`)

- Async Pigeon `seek` + `playFromCurrentPosition` (no re-enter seek-zero after scrub).
- Clear stale `pendingNavigationActivation` on scrub complete.
- `playbackSeekEpoch` invalidates overlapping loop seek-zero vs user seek.
- Zero-tolerance scrub seek with **450ms Host wall-clock timeout** + **900ms Dart timeout**
  so Coordinator `_enqueue` cannot deadlock when AVPlayer omits seek callbacks (observed on
  8–10s local clips).

## Preview end-cap, Option B drift gate, and mid-path zero tolerance (`b2ceabd`)

**Shipped in work commit `b2ceabd`** (docs in Commit 2). Three layers work
together:

| Layer | Behaviour |
|-------|-----------|
| Host tolerance | Exact (zero) for all in-range preview requests; infinite only past asset duration |
| Option B (Dart) | Reject when `\|requested − actual\| > 1.0s`; `forbidBorrow`; no `lastSuccessful` write |
| End-cap | `duration − ε` request path; failure forbids borrow (tail watermark) |

**Not changed:** 1.0s preview bucket, whole-second scrub seek on release, §2.1
borrow rules for ordinary Host nil.

### DiagnosticBenchmark (pre-commit device gate; harness removed in `b2ceabd`)

Profile builds ran a one-shot Host benchmark per asset on first prepare (harness
not in shipping binary). Each asset: probe seconds **5 / 10 / 14 / 15** when
`duration ≥ 15.5s`, else proportional floors; for each second, **infinite then
zero** tolerance via `AVAssetImageGenerator`.

**Aggregate (5 assets, 22 zero-tolerance shots):**

| Metric | Result |
|--------|--------|
| `zeroOk` / `zeroFail` | **22 / 0** (0% failure) |
| `zeroFailInfOk` | **0** (no position where infinite succeeded and zero failed) |
| Zero latency min / max / typical | **14 ms / 388 ms**; most shots ~50–150 ms |

**Per-asset summary:**

| Device | Asset prefix | Duration | Positions | zeroOk | zeroMs min–max (avg) | Notes |

### Kafka hold validation — iPhone13pro (`b2ceabd` Profile, 2026-08-31)

**Purpose:** Distinguish acceptable slow decode from drift-reject permanent black.

| Observation | Result |
|-------------|--------|
| Build | mid-path zero + Option B (shipping code in `b2ceabd`) |
| Session `driftReject` count | **0** |
| Hold at ~10s (multiple samples) | `previewAccepted` wallMs **43–66**; user confirmed **real frame appears**, not infinite black |
| Owner sign-off | 「这次没有出现无限黑，最终会出来真实帧」 |

**Acceptance expectation for >350 ms:** brief `#000000` placeholder (or §2.1 borrow
when eligible), then correct JPEG — **not** hold-stall black caused by repeated
`driftReject` on the same second.
