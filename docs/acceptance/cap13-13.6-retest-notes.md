## Storage observation (gate-foundation; write this down)

Photos: **Optimize iPhone Storage** was ON. iOS **does** reclaim (reboot **255.22 → 200.2 GB**). It does **not** reclaim as fast as PhotoKit writes while Browse is fetching.

WakeTok JPEG temps are bounded (display ≤2, preview ≤3). Growth is **Photos library cache** from `requestAVAsset` (`isNetworkAccessAllowed = true`).

### Replication after reboot (not a numbered Hitch-matrix row)

That V1 lasted **~75 s**. Owner **waited for only the first and last videos** to finish iCloud download and become playable. **Every iCloud video in between was flicked away as soon as a cover/spinner was visible** — no dwell for Layer 2.

## Mechanism (for the next capability; not a 13.6 code patch)

- `_loadVideo` awaits `requestPlayableVideo` (networked high-quality `requestAVAsset`, DTO is only `assetIdentifier` + `durationSeconds`; **feed discards the return value**) then `setPlaybackPlan` / `load` → `prepareActive` (a **second** networked `requestAVAsset`).
- Leave current: `pause()` + `cancelPlayableVideo`. `prepareActive` is cancelled only when the next item calls `replaceCurrentItem` inside `load()`, which is **after** the next `requestPlayableVideo` await. Fast skip of iCloud videos can leave the previous `prepareActive` running.
- App **cannot** delete Photos-library downloads. Session-end can only cancel in-flight requests and drop JPEG temps. Reclaim = iOS Optimize Storage (idle / reboot).
