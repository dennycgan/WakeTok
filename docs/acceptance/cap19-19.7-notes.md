## Preferences (KV already in 19.6)

| Key | Default | Settings UI |
|-----|---------|-------------|
| `waketok.cap19.leftSwipeAddEnabled` | `true` | Master switch |
| `waketok.cap19.leftSwipeGuideEnabled` | `true` | Sub switch; disabled UI when master off |

**Master→tip sync (19.7 Settings):** when the user flips the master
switch, the tip switch is set to the **same** value in one step (UI +
`leftSwipeGuideEnabled` KV). Greyed tip still shows the synced off state.
Independent tip toggle remains available only while master is on.

Immediate effect: writing Settings invalidates / reloads append arming + guide host (no app kill).

## Duplicate scope (left-swipe only)

**Why not the half-sheet picker:** Left-swipe is low-friction and easy to
repeat on the same item while browsing. Opening the Cap 19 sheet, choosing
the same album again, and confirming is a deliberate multi-step action —
accidental duplicate rate is much lower. Cap 19.7 hardens the left-swipe
path only. Panel same-album re-tap is an **intentional exclusion** by
frequency asymmetry, not an oversight; reopen if real complaints appear.

## Guide replay semantics

`sessionGuideShown` means: **this launch, the guide was actually shown**
(not “master was ever on”).

| Scenario | Behaviour |
|----------|-----------|
| Guide shown once → Settings master off → on (same launch) | Guide does **not** show again (**A** / W-19.7-6) |
| Cold start with master **off** (guide never shown) → mid-launch master **on** | Guide **may** show once (unused opportunity retained — default clarification, not A′) |

A′ (forfeit opportunity if master off at cold start) is **rejected**: tip
exists to teach the gesture when it first becomes usable.
