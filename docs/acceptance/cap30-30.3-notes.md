## Shared orchestrator (hard requirement)

For the entire app `ProviderScope` / process lifetime, the Cap 30 `<1>` Host
and the Cap 19 left-swipe tip D6 check **must** read the **same**
`Cap30FirstLaunchGuideOrchestrator` instance from
`cap30FirstLaunchGuideOrchestratorProvider`. `chainArmedThisLaunch` is process
memory on that object only.

## Page-change signal (accepted simplification)

Cap 30.3 treats any change to `mainBrowseFeedIndexProvider` while `<1>` is
active as equivalent to a vertical PageView page change (Q2 early-end). The
Host does **not** distinguish user swipes from other index writers (e.g. rare
session rebuild). That conflation is an accepted simplification for
first-launch; no separate filter is implemented.

## disk=2 interim (accepted)

After `<1>` completes, the orchestrator enters `<2>` (disk=2) with no `<2>` UI
until 30.4. D6 may keep blocking the Cap 19 tip in that window. Accepted
interim for internal builds only; not a store-facing release state (Cap 30
ships only after close-out).
