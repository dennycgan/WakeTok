## Dual Album overlap — not in 11.6 (D2=A)

11.6 does **not** run a two-User-Album intersection.

Photos⊆All already exercises the real-device identity risk: the same
`PHAsset` is enumerated by two different `PHFetchResult` queries
(mediaType Photos vs entire-library All) and coalesce compares
`localIdentifier`. All’s `contrib < raw` on device is that check.

That is the **same class** of identity/dedupe question two albums must
answer. It is **not** the same PhotoKit fetch shape: dual albums add
`fetchAssets(in: collection)` plus user membership. That extra path is
deferred to **Cap 14 (Build-a-Pool UI, real multi-select SPD)** — not
parked indefinitely.
