## Residual absorbed in 17.6 — Live L2→motion dual-phase chrome

**Symptom (Kafka iCloud Live):** gold spinner → Still loading → both
clear → LIVE drops → L2→motion handoff → gold spinner again pushes LIVE
up → spin → play.

**Cause:** two sequential waits (L2 still, then Live prepare) share
corner chrome; Cap 17.3 F1 &lt;T suppress on `_livePreparing` opened a
~150 ms dip after a long L2 wait that had already painted spinner
(14.6b same-frame handoff intent undone for that case).

**Fix (`a42abcd` / ADR-037):** `_layer2WaitChromeLatched` — if L2 wait
spinner painted this inFlight, motion prepare **skips** F1 &lt;T.
Reassure stays L2-only (A1). Short / unlatched prepares keep F1.
`_prepareLiveMotion` vs `_playLiveMotionOnce` split (replay must not
re-arm preparing chrome; no fake Host `isPrepared` API).
